# Render deployment

The app is configured for Render's Node runtime. Render should run `npm ci && npm run build` and then `npm start`. The `RENDER=true` build flag switches Nitro from the Vercel output preset to the native Node server output at `.output/server/index.mjs`.

`render.yaml` defines a free Frankfurt web service and free PostgreSQL database. Keep provider credentials and `ADMIN_PASSWORD_HASH` as Render secrets. `SESSION_SECRET` is generated by Render. Redis and provider keys remain pending until the corresponding managed service or provider is connected.

The remaining handoff requirement is a Git repository URL that Render can clone. This workspace has no Git remote, and the GitHub connector is enabled in Manus configuration but its CLI is not exposed inside the current sandbox. Once a repository URL is available, create the Render service from the Blueprint or call Render's service creation endpoint with that URL, then inspect build/deploy logs and set the health check.

Before production use, replace the current preview Crew unlock behavior with the server-side Argon2id session flow described in `docs/DEPLOYMENT.md` and supply real provider credentials. Do not use the initial password as a browser-side value.
